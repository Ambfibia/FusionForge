# Server-owned Coco eggs

Question: why do protocol-0104 shiny packets produce no visible eggs in FFOne?
Source role: current primary, Retrobution 20260821. No donor substitution.

FFOne's `upsert_shiny` already publishes network identity, session ownership,
position and visibility. It had no model consumer. The production shiny table
selects `shineni_Item` and `shineni_buff`, neither previously published as a
native world model. The equipment model `shineni_ai` is not a substitute.

`cnShinyContainer.Add` indexes table 11 section 0 with packet `iShinyType`,
then section 2 with the row's `m_iMesh`. It instantiates at converted server
position and identity rotation. `SetupShiny` loads the exact male model field,
replaces the instantiated model's root position and rotation, retains authored
scale and parents it to the shiny. Main/sub atlas overrides are conditional;
both accepted egg rows declare `null`, so their authored textures remain intact.

FFOne resolves the same table rows into semantic `native_asset_routes` entries,
loads each GLB under its existing server-owned entity, normalizes the model root
without a character half-turn and plays `stand1`. Repeat appearance updates keep
one visual. Type changes replace it; network deletion/session teardown removes
the visual descendants. No local spawns or respawn timers are introduced.
Unknown or unpublished rows produce a diagnostic, not substitute geometry.

## Native payload and acceptance

`Tutorial.resourceFile` exports both exact `mob/shineni_*.kfm` routes. See
`recipes/native/characters/coco-eggs-primary-20260910.receipt.json` for scoped
object identities, hashes, four final files and deterministic replay command.
The publisher remains in `tools/legacy-sources/publish-coco-eggs.py`. Replay
re-extracts and converts both models, verifies the complete output set and bytes,
then atomically installs individual files and inserts only missing semantic
model routes into the existing table document.

Both conversions preserve eight nodes, one skinned mesh, three joints,
92 weighted vertices, one animation and their distinct 128x128 authored atlases.
Semantic roundtrip and tree audits pass. Independent GPU previews at the
`stand1` midpoint loaded both complete scenes, sampled an AnimationPlayer and
rendered 148,378 foreground pixels each, with zero material or shader errors.
Reports and images live under `work/cases/coco-eggs-20260910/{item,buff}-gpu`.
GPU smoke proves native rendering; it does not claim screenshot parity with a
running legacy client or prove a live shard sent eggs at a player's location.

`cargo test -p ffone-client --lib network_world_runtime::shiny::tests` passed
all four tests: production table/model/image references, root scale/facing,
duplicate packets/type replacement/recursive deletion, and delayed animation
loading with exactly one graph assignment.
`cargo build -p ffone-client --bin ffone-client --locked` also passed for the
ordinary development executable. The current shared runtime registration had
exceeded Bevy's system-tuple arity; moving the existing vehicle-weapon visibility
system to a separate `add_systems(Update, ...)` preserved its scheduling semantics
and removed that compile blocker.

This change addresses missing world visuals. Pickup requests, rewards, minimap
markers and appearance/pickup effects are separate consumers, not acceptance
claims of this repair.

## Follow-up audit: pickup and animation effects

The requested follow-up is an audit, not an acceptance of complete egg gameplay.
No runtime behavior or binary assets were changed by this audit.

Both installed GLBs were run again in `logical_model_gpu_preview` with
`--animation-name stand1`, without midpoint freezing. The reports
`work/cases/coco-eggs-20260910/item-animated.json` and `buff-animated.json`
record successful scene/dependency loading, 69/68 animation evaluation frames,
one graph/player each and zero material/shader errors. Source `stand1` loops
with duration 3.33333158493042 seconds. The publisher's semantic roundtrip
proof covers its preserved native animation channels.

Missing runtime paths:

1. `cnAvatarAttack.CheckShiny` implements automatic proximity pickup while the
   player is alive and the containing update reaches the normal movement path.
   It invokes the table's positive `m_iGetEffect`, otherwise ES397, plays
   `Egg_Pickup`, sends `P_CL2FE_REQ_SHINY_PICKUP`, and deletes the local shiny.
   Every production shiny row currently has `m_iGetEffect == 0`. The native
   client has wire definitions but no pickup request call site. It therefore
   cannot reach the associated local effect/sound path either.
2. At 0.10000000149011612 seconds, the item egg's preserved `particle` animation
   event selects ES398; the buff egg selects ES401. The current shiny runtime
   starts the graph but has no animation-event consumer. NPC event processing
   only queries NPC-owned players and cannot cover shiny entities.
3. ES397, ES398 and ES401 are absent from the native effect catalog. Their
   original routes exist in raw primary `Effects.resourceFile`, serialized
   asset `CustomAssetBundle-fa9dbcf4604f64024b06ff1d5e375918`. A raw
   `fusionforge list-assetbundle` resolves the exact routes
   `prefabs/particle/effectscripts/es[397].prefab`, `es[398].prefab`,
   `es[401].prefab` to root pointers 9344, 10965 and 9808 respectively.
   This is discovery evidence; complete dependency recovery and native
   publication have not been accepted by this audit.
4. `Egg_Pickup` itself is already declared in `native_asset_routes` as
   `sfx/shared/egg_pickup`; its OGG exists. The missing piece is invocation.
5. Primary `GameFrame` routes `SHINY_PICKUP_SUCC` to
   `cnDisplayMapName.ShinyIcon`: reward/buff icon and localized chat notification.
   No matching response handler exists in the current native client. The world
   pickup effect belongs to local pickup, not that success response.

The raw primary `main.unity3d` and both managed payload hashes were reverified
against the exact assembly evidence used above and
`reports/nano-summon-primary/assembly-firstpass.evidence.json` before tracing
`AnimationEventHandler.particle`. `end` at 3.0833334922790527 seconds only
delegates to an optional `pEndAnimation`; this audit does not invent a shiny
completion callback or treat it as a second pickup effect.

Remaining implementation must preserve local pickup ordering, server-owned
rewards, animation loop crossings and effect attachment/cleanup, and publish
semantic native effect data. Do not extend the existing legacy closure format
with new Unity identities in the native repository. Success UI requires the
usual primary UI evidence and EN/RU localization pass.
