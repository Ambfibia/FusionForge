# Fred eye deformation — 2026-09-10

The owner's screenshots identify angular pupil tears in animated
`npc_fredfredburger2`. The defect reproduces in the native `stand1` clip and
disappears in the unanimated bind pose. The PNG contains an intact round pupil.

## Cause and native contract

Primary `DongResources_05_06.resourceFile`, serialized asset
`CustomAssetBundle-cc046f909412b47d6ace39b333bffa08`, Mesh 423 and
SkinnedMeshRenderer 555 own the character skin. Renderer `m_Quality` is Auto (0).
Primary `main.unity3d`, `mainData`, QualitySettings 14 selects default WebPlayer
quality 3 (Good), with `blendWeights = 2`. The named WebPlayer profile also uses
two weights. Higher Beautiful/Fantastic profiles contain four; this fix bakes
the default contract and does not claim to implement selectable legacy quality.

The installed GLB faithfully retained all four source influences. Independent
decoding consumes all 3,577 packed weights and 4,170 packed indices, matches
all 1,880 native vertices, and proves this is not a packed-stream alignment bug.
All 44 pupil-influenced vertices have three or four weights. Their first two
influences are predominantly Head/Pupil; later influences include Neck and even
the opposite eyelid. Applying those later influences folds the eye surface.

The repair retains the first two influences in source order, renormalizes them,
and zeroes the other two. It changes 593 vertices across this one model to
preserve the renderer-wide source setting. Only WEIGHTS_0 bytes change: palette,
positions, indices, normals, UVs, bind matrices, animations, materials, texture
bytes and shared texture references are byte-identical. No global skinning
policy or other character is changed.
